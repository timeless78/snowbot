## 개발 환경 (인계 자료와 다름)

- **Android API 28 이상**(인계 자료는 26+), Gradle 8.0 이상, Java 또는 Kotlin.
- 공모전 페이지가 소개하는 Pleos Connect SDK: **Vehicle**(차량 상태), **FusedLocation**(위치), **NaviHelper**(길 안내 연동), **TextToSpeech · SpeechToText**(음성 입출력).
  인계 자료의 "Gleo AI SDK(STT·TTS·**LLM**)"는 이 목록에 **LLM 이 없다**. LLM 을 쓸 수 있는지는 Pleos 개발 문서에서 확인해야 한다.
- 에뮬레이터로 구동 검증 가능. 예시: 음성 메모 앱(STT), 안전운전 점수 앱(Vehicle), 배달 기사용 앱(NaviHelper).

## 권리·유의사항 (요약)

- 순수 창작물, 타 공모전 수상작 불가. 제3자 권리 침해 책임은 응모자.
- 출품 자료 지식재산권은 응모자. **수상작은 주최 측이 통상실시권, 결과 발표 후 4개월 우선협상권을 가질 수 있다**(조건은 협의).
- 상금은 대표자에게 일괄 지급, 제세공과금 원천징수.
- 현대자동차그룹 임직원은 참가 가능하나 수상 제외.

## 우리 계획에 미치는 영향

1. **하드웨어(SnowBot) 동반 출품 허용 여부는 요강에 없다.** 심사 대상은 앱(APK)이고, PT 시연은 "에뮬레이터 화면 또는 기기". 외부 모듈을 금지하는 말도 없다.
   → 앱이 **모듈 없이도 동작**(가상 SnowBot)하게 하는 기존 방향이 맞다. SnowBot 실물은 PT 에서 "보조 시연"으로 쓸 수 있는지 **설명회(10/28)에서 묻거나 이메일 문의**한다 (아래 초안).
2. **가산점을 노린다.** 마감 전에 에뮬레이터에서 도는 최소 앱(가상 SnowBot + 스킬 1개) + 시연 영상 + GitHub(APK)를 내면 가산점. 20일 안에 가능한 범위로.
3. **사업성 숫자가 필요하다.** 타깃 고객, 예상 MAU, Retention Rate, 확대 계획을 기획서 6번에 써야 한다.
4. **LLM 사용 가능 여부 확인.** 공모전이 소개한 SDK 에는 STT·TTS 만 있다. 대화형 기능은 외부 LLM API(서버 경유) 또는 규칙 기반으로 설계해야 할 수 있다.
5. **숏폼은 SnowBot 의 강점.** 움직이는 눈사람 로봇은 세로 영상에 잘 맞는다. 본상과 별도로 도전할 만하다(가산점은 없음).
6. 12/3~4 서울 오프라인 PT, 2027-02 행사 현장 참석이 필요하다(선정 시).

## 온라인 설명회 다시보기에서 확인한 것 (2026-11-01)

**위 정리와 다르거나 새로 알게 된 것**
- **이메일 제목에 앱명을 넣는다:** `[차량용 앱 개발 공모전] 앱명_팀명(개인은 이름)`. 고쳐 낼 때는 앞에 `[수정제출]`. **참가자 전원을 참조(CC)에 넣는다** (09:13, 12:10). 개인 참가는 본인 한 명. 괄호·밑줄 같은 구분 기호는 화면에만 나와서 자막으로는 확인하지 못했다. 보내기 전에 홈페이지 "지원·제출 방법"에서 다시 확인한다.
- **TTS·STT·FusedLocation 도 지금 쓸 수 있다.** 공모전 개발 단계에서는 Vehicle·NaviHelper·STT·TTS·FusedLocation 을 승인 없이 **매니페스트 권한 선언만으로** 쓴다. 승인은 앱 마켓 배포 심사 때 확인한다 (32:29, 38:17). 04·05 문서의 "준비 중(신청 불가)"는 공모전에는 해당하지 않는다. 에뮬레이터에서 실제로 되는지는 시험해 봐야 한다.
- 아직 공개되지 않은 SDK 까지 공모전에 제공할 예정이라고 했다 (26:01). 어떤 SDK 인지는 말하지 않았다.
- **외부 API 와 공용 네트워크를 함께 써도 된다** (37:56). → 문의 초안 4번 해결.
- **실차 시연은 없다.** PT 검증은 에뮬레이터로 한다 (21:10).
- **생성형 AI 로 기획서·코드를 만들어도 된다.** 다만 참가자가 전체 구조와 로직을 이해하고 **2차 PT 기술 Q&A 에서 직접 설명할 수 있어야 한다** (20:35).
- APK 는 이메일 첨부가 아니라 **GitHub 링크**로 낸다. 저장소의 APK 폴더나 Releases 에 둔다. README 에는 앱 이름, 한 줄 소개, 실행 방법, 테스트 환경, 필요한 설정, APK 위치를 쓴다. **비공개 저장소도 되며**, 공지된 심사용 계정을 Collaborator 로 초대하고 마감 전에 접근이 되는지 확인한다 (10:34~11:09).
- **아이디어 특별상도 개발 산출물을 내야 한다.** 완성도가 조금 부족해도 혁신성·발전 가능성으로 뽑는 상이다 (06:14).
- 1차에 낸 개발 결과물은 PT 전까지 보완할 수 있다. 최종 순위는 2차 결과물과 PT 를 합쳐 정한다 (08:06, 14:11).
- 숏폼: 초상권·저작권은 응모자 책임이고, **차량 내외부 이미지 노출은 최소화**하라고 했다 (17:32). 상금은 화면 기준 50만 원이다(진행자가 "500만 원"이라고 잘못 말함).
- 복수 출품은 개수 제한 없이 된다. 앱명으로 구분한다 (19:04).
- 42dot 의 조언: **"SDK 를 많이 쓰는 것 자체가 목적이 아니다.** 문제 해결에 필요한 SDK 를 골라 핵심 기능에 어떻게 쓰이는지 분명히 보여 주라" (32:02). 또 "차량 환경에서만 줄 수 있는 핵심 가치 하나를 정해, 실제 동작하는 기능으로 보여 주는 것부터 시작하라" (36:33).
