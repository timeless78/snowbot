# 프로토타입 서버 (2026-10-27)

모두의AI실험실 클라우드 자원 신청이 승인됐다. 이 서버를 **방법 1(프로토타입) 의 클라우드 서버**로 쓴다 — 스노봇과 에뮬레이터 차량 앱이 둘 다 여기에 WebSocket 으로 붙는다(07 문서 8-1절).

> GitHub 에 올리기 전에 이 문서의 IP 를 지운다(공모전 안내: 공유 자료에 계정·개인정보 노출 금지). 비밀번호·PEM 키 내용은 어디에도 적지 않는다.

| 신청 시 프로젝트명 | "웹툰 레거시 홈페이지" — 스노봇 용도로 써도 되는지 이용 규정 확인 필요 |

## 지금 상태 (2026-10-27 20:30 확인)

- [x] 패키지 전체 업데이트 + 재부팅(커널 553.144.1)
- [x] 스왑 2GB (`/swapfile`, 재부팅 후에도 유지)

- [x] 바깥에서 포트 3000·80 접속 확인 (임시 테스트 페이지로 확인 후 지움)
- [x] 비밀번호 로그인 끔 (사용자 결정) — `PasswordAuthentication no`, `PermitRootLogin prohibit-password`. 원본은 `/etc/ssh/sshd_config.bak-20261027`. 키 파일을 잃으면 포털 콘솔로 들어가 되돌린다
- [x] **중계 서버 설치 (2026-10-27 21:24)** — 코드 [../server/](../server/README.md), 서비스 `snowbot-relay`(포트 3000, `snowbot` 사용자, 재부팅 시 자동 시작), DB `/var/lib/snowbot/relay.db`. 맥에서 시험 7개 통과
- [x] **인터넷 너머 왕복 확인** — 맥에서 가상 스노봇(`SIM-01-9B33`)과 가상 앱을 서버에 붙여: 앱 → 서버 → 스노봇 표정 명령(sleepy·nod·"조금 쉬어갈까요?"), 스노봇 → 서버 → 앱 센서 값(CO₂) 전달 성공
- [x] **암호화 연결 (2026-10-27 22:1x)** — Caddy 2.11.7 + Let's Encrypt 인증서(`<서버-IP>.sslip.io`, 만료 2027-01-25, 자동 갱신). 설정 [../server/deploy/Caddyfile](../server/deploy/Caddyfile). 중계 서버는 서버 안(127.0.0.1:3000)에서만 받고 **바깥 3000 은 닫힘**, 80 은 https 로 넘김
  - 주소: **`wss://<서버-IP>.sslip.io/ws`**, `https://<서버-IP>.sslip.io/api/pair`, `/health`
  - 서버를 옮기면 IP 가 바뀌므로 주소도 바뀐다 → 스노봇·앱은 주소를 설정값으로 둔다
- [x] **지연 시간 측정** — 맥(집 유선) → 서버 → 가상 스노봇 → 서버 → 맥 왕복 150번: **중간 6ms, 90% 7ms, 최대 55ms**. 서버 중계 자체는 거의 시간이 안 든다
  - 실제 스노봇(Wi-Fi)·폰 핫스팟(LTE)·차량 통신망은 무선 구간이 더해진다 — 실물 도착 후 다시 잰다 (LTE 는 구간마다 수십 ms 예상, 추정)
  - 서버는 ping(ICMP)에 답하지 않는다(NCP 설정) — 측정은 위 도구로 한다
- [ ] AI 연결 (STT·LLM·TTS), 음성 조각 전송

## 기간 문제

- 서버가 **11/27 에 끝나는데 2차 PT 는 12/3~4** 이다. 연장 신청은 **종료 2주 전(11/13 무렵)부터, 1회**만 가능 → **11/13 에 연장 신청**해야 PT 때 서버가 살아 있다.
- 최종 선정 시 2027-02 전시까지 서버가 필요하다. 그때는 다른 서버(유료 또는 재신청)로 옮긴다. 서버 설정을 스크립트로 남겨 두면 옮기기 쉽다.
